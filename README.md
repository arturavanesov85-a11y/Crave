# CRAVE — сайты и CRM

Одно приложение на Next.js: сайт проката, сайты автосалона и сервиса и CRM для сотрудников. База — SQLite (файл `prisma/dev.db`), ничего дополнительно устанавливать не нужно.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. При первом запуске база создаётся и заполняется автоматически: 8 автомобилей с тарифами текущего сайта, пользователи для каждой роли и несколько демо-заказов.

| Адрес | Что это |
|---|---|
| http://localhost:3000 | Сайт проката |
| http://localhost:3000/auto | Сайт автосалона (CRAVE Auto) |
| http://localhost:3000/service | Сайт сервиса (CRAVE Service) |
| http://localhost:3000/crm | CRM |

Сбросить базу к начальному состоянию: `npm run db:reset`. Тесты: `npm test`.

## Сценарий для проверки

1. На сайте выберите даты → автомобиль → отправьте заявку. Машина получает временный резерв на 30 минут.
2. В CRM под менеджером: «Сегодня» → заявка → «Взять в работу» → «Подтвердить бронь». Стоимость начисляется по снимку условий.
3. «Оплаты» → принять оплату и залог. Залог учитывается отдельно и не считается выручкой.
4. «Провести выдачу» → пробег, топливо, фото (с телефона откроется камера). Затем «Принять возврат» → предложенные доплаты, новые повреждения.
5. Удержание из залога: менеджер запрашивает, руководитель подтверждает.
6. Вернуть залог (руководитель или финансист) → «Закрыть заказ».
7. Попробуйте занять ту же машину на пересекающиеся даты — система откажет, учитывая 3 часа подготовки.

## Что сделано

- **Сайт проката:** выбор дат на первом экране, каталог с фильтрами и ценой за весь срок, карточка машины с калькулятором, цены в режимах «Рассчитать» и «Все тарифы», условия, контакты, заявка, перенаправления со старых адресов, `sitemap.xml`.
- **Один расчёт стоимости** (`lib/pricing.ts`) для сайта и CRM: сайт получает расчёт только с сервера.
- **Бронирование** (`lib/booking.ts`): временные резервы с истечением, брони, аренда, ТО и блокировки, буфер подготовки, просрочка возврата продолжает занимать машину. Проверка и запись выполняются атомарно.
- **CRM:**
  - «Сегодня»;
  - календарь (день, неделя, месяц);
  - заказы и карточка заказа с вкладками;
  - продление, замена машины, отмена и неявка;
  - осмотры с фото;
  - автопарк: тарифы с версиями, документы, ТО, повреждения;
  - клиенты с ограничением по направлениям;
  - заявки трёх направлений;
  - финансы: отчёты, журнал, сторно, экспорт CSV;
  - настройки правил и пользователей, журнал изменений.
- **Права** проверяются на сервере в каждом действии и при выдаче фото.
- **Журнал операций** только дополняется: изменить или удалить запись не даёт база. Исправления — сторно.

## Предположения и чего нет

- Правила округления суток, предоплаты, опоздания и буфера — **предположения** (помечены в расчётах). Их меняют в CRM → «Настройки».
- Тарифы перенесены с текущего сайта и ждут подтверждения владельцем (`docs/01-missing-data.md`).
- Нет: онлайн-оплаты, реальных уведомлений (SMS, Telegram), загрузки документов клиента, договоров, модулей продаж и сервиса (кроме заявок). Фото автомобилей — заглушки.
- SQLite подходит для теста и небольшой нагрузки. Для продакшена: `provider = "postgresql"` в `prisma/schema.prisma` и `DATABASE_URL` на сервер PostgreSQL, плюс ограничение `EXCLUDE` (см. `docs/02-architecture.md`).
