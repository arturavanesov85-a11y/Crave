# CRAVE — сайты и CRM

Одно приложение на Next.js: сайт проката, сайты автосалона и сервиса и CRM для сотрудников. База — SQLite (файл `prisma/dev.db`), ничего дополнительно устанавливать не нужно.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. При первом запуске база создаётся и заполняется автоматически: 8 автомобилей с тарифами текущего сайта и учётная запись владельца. Клиентов, заказов и машин в продаже нет — база чистая.

| Адрес | Что это |
|---|---|
| http://localhost:3000 | Сайт проката |
| http://localhost:3000/auto | Сайт автосалона (CRAVE Auto) |
| http://localhost:3000/service | Сайт сервиса (CRAVE Service) |
| http://localhost:3000/crm | CRM |

Сбросить базу к начальному состоянию: `npm run db:reset`. Тесты: `npm test`.

## Домены на сервере

Один сервер обслуживает три сайта. Сайт проката самостоятельный: на нём нет переключателя на автосалон и сервис. На сайтах автосалона и сервиса есть кнопка «Прокат».

| Домен | Сайт |
|---|---|
| crave-rental.ru | Прокат и CRM (`/crm`) |
| crave-auto.ru | Автосалон |
| crave-service.ru | Сервис |

Перед сборкой (`npm run build`) задайте в `.env` переменные из `.env.example`: `NEXT_PUBLIC_URL_*` — адреса для ссылок, `SITE_HOST_AUTO` и `SITE_HOST_SERVICE` — по ним сервер понимает, какой сайт открыть. Локально эти переменные не нужны.

## Сотрудники и доступы

Владелец управляет сотрудниками: CRM → «Настройки» → «Управлять сотрудниками». Там можно добавить, заблокировать и удалить сотрудника, сменить ему пароль и роль, а также точечно включить или выключить права по разделам и направлениям. Разделы без доступа сотрудник не видит в меню, а сервер не выполняет его действия в этих разделах.

## Продажи и сервис в CRM

- **Продажи** и **Сервис** — рабочие зоны для заявок с сайтов автосалона и сервиса, как «Заказы» у проката. Доска по этапам, свои и все заявки, просроченные действия. В карточке заявки: ответственный, следующее действие с датой, сумма сделки или оценка работ, для сервиса — время записи, для продаж — машина из наличия, комментарии и история. Заявку можно создать и вручную.
- **Сайт сервиса** — услуги (название, описание, цена «от», порядок, видимость) и тексты страницы.

## Мини-приложение Telegram

Каталог машин для сотрудников: «В наличии», «В пути», «Под заказ», поиск, фильтр по марке, карточка с фото и характеристиками. Адрес — `/tg`. Машины и сроки поставки ведутся в CRM → «Салон» → «Авто в продаже» (поля «Наличие», «Ожидаемая дата прибытия», «Срок поставки»). На сайт автосалона попадают только машины «В наличии». В приложении сотрудники видят и черновики (с пометкой «черновик»), на сайте их нет.

Подключение (нужен сервер с https — Telegram не открывает обычный http):

1. В Telegram откройте @BotFather → `/newbot` → имя и адрес бота. Скопируйте токен.
2. На сервере в `.env` задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME`, перезапустите приложение.
3. В @BotFather: `/newapp` → выберите бота → адрес `https://<домен CRM>/tg`. Получите ссылку вида `t.me/<бот>/<app>` — её можно закрепить в канале сотрудников.
4. По желанию: `/setmenubutton` → тот же адрес — кнопка приложения в чате с ботом.
5. Сотрудник открывает приложение → появляется запрос. Владелец: CRM → «Настройки» → «Доступ из Telegram» → привязать к сотруднику. Нужно право «Мини-приложение Telegram» (есть у роли «Сотрудник автосалона», остальным — в настройках сотрудника).

Без Telegram приложение можно открыть в браузере по адресу `/tg`, войдя в CRM.

### Разделы приложения: «Салон» и «Прокат»

Наверху приложения — переключатель **Салон / Прокат**. Кнопка раздела видна, только если у сотрудника есть право: «Приложение Telegram: «Салон»» (`tg.app`) и «Приложение Telegram: «Прокат»» (`tg.rental`). Вкладка **«Черновики»** в «Салоне» — право `tg.drafts` (владелец и роль «Руководитель автосалона»); остальные сотрудники черновиков не видят.

«Прокат» (`/tg/rental`): дела на сегодня и завтра (заявки, выдачи, возвраты, просрочки, подготовка машин, удержания на подтверждение), карточка заказа (звонок, деньги, оплата и залог, продление, запрос удержания, комментарий, акты, документы клиента), выдача и возврат с фото (зоны кузова, фото к каждому повреждению, фото уменьшаются в телефоне), свободные машины на даты и новая бронь. Сотрудник выдачи видит только назначенные ему заказы.

### Уведомления в Telegram

Бот сотрудников пишет тем, у кого есть нужное право (и кто разрешил боту писать — кнопка «Разрешить» в приложении):
- новая заявка на аренду с сайта — с кнопкой «Взять в работу» прямо в чате; заявки автосалона и сервиса — тем, кто их ведёт;
- запрос на удержание из залога — руководителю, с кнопками «Подтвердить» / «Отклонить»;
- за 90 минут до выдачи и возврата — сотруднику выдачи и ответственному; просрочка возврата — раз в сутки;
- документы и ТО — за 14 и 3 дня; сводка по прокату в 9:00.

Кнопки работают через вебхук `/api/tg/webhook` (секрет `TELEGRAM_WEBHOOK_SECRET`), расписание — через `/api/cron/tick` каждые 5 минут (ключ `CRON_SECRET`, cron на сервере). Повторно одно и то же уведомление не отправляется (таблица `Notification`).

### Клиентский бот и акты

Отдельный бот для клиентов (`TELEGRAM_CLIENT_BOT_TOKEN`, вебхук `/api/tg/client-webhook`): клиент делится номером телефона — бот находит его в базе. Дальше он получает подтверждение брони, напоминание за 2 часа до выдачи и **акт приёма-передачи в PDF** с фото осмотра после выдачи и возврата. Акты скачиваются и из CRM / приложения: `/api/orders/<id>/act?kind=pickup|return`.

Документы клиента (паспорт, права) загружаются в карточке клиента и заказа; смотреть — право «Документы клиентов».

## Автосалон в CRM

Роли «Владелец» и «Сотрудник автосалона»:

- **Авто в продаже** — добавление и редактирование машин для сайта автосалона: характеристики, цена (пусто — «цена по запросу»), описание, комплектация, фото с выбором обложки и порядка. Можно взять характеристики и фото из автопарка проката. На сайте видны статусы «В продаже» и «Забронирован».
- **Сайт автосалона** — тексты главной страницы, телефон, адрес и часы работы.
- **Порядок** машин на сайте и в мини-приложении меняется перетаскиванием строки списка за значок ⠿.
- **Бронь и продажа** — кнопки «Забронировать» / «Продано» в списке и в карточке: обязательны имя и телефон клиента и стоимость; записывается менеджер. Клиент попадает в базу клиентов (направление «Продажи»). В карточке — данные покупателя для ДКП (шаблоны ДКП с выбором продавца будут добавлены), история броней и продаж. «Снять бронь» / «Вернуть в продажу» сохраняют запись в истории.
- **Цена с НДС** — галочка в объявлении; на сайте перед суммой пишется «Цена с НДС».
- **КП в PDF** — в карточке машины (CRM) и кнопкой «Выгрузить КП» в мини-приложении (бот присылает PDF в чат). Стоимость подставляется из объявления, менеджер может её изменить. Комплектация: строка с двоеточием на конце — заголовок группы. Шрифты PDF — `assets/fonts` (Noto Serif, OFL).
- **Выгрузить в Excel** — все машины с характеристиками и текущей сделкой (только CRM).

Фото объявлений хранятся в `storage/public` (не в git) и отдаются по адресу `/media/...`. Фото машин проката лежат в `public/cars` и взяты с crave-rental.ru.

**Фото машин проката** меняются в CRM: «Прокат» → «Автомобили» → машина → «Фото на сайте». Можно загрузить новые, выбрать обложку для каталога, поменять порядок и удалить лишние. Новые фото сохраняются в `storage/public/rental`.

## CRM: вход

При первом заполнении базы создаётся только владелец: e-mail — `SEED_OWNER_EMAIL` (по умолчанию `owner@crave.test`), пароль — `SEED_PASSWORD` из `.env`. Остальных сотрудников владелец добавляет в CRM: «Настройки» → «Сотрудники».

На сервере задайте свой `SEED_PASSWORD` до первого запуска: с паролем по умолчанию заполнение в production не запустится.

Для проверки ролей и демо-данных (только локально, на пустой базе):

- `SEED_TEST_USERS=1` — добавляет тестовых сотрудников с тем же паролем: head@, manager@, handover@, finance@, sales@, service@, admin@ (домен `crave.test`).
- `SEED_DEMO=1` — добавляет тестовых сотрудников, демо-клиентов и заказы.

Например: `SEED_DEMO=1 npm run db:reset` (удаляет все данные в базе).

## Сценарий для проверки

1. На сайте выберите даты → автомобиль → отправьте заявку. Машина получает временный резерв на 30 минут.
2. В CRM (владелец или менеджер проката): «Сегодня» → заявка → «Взять в работу» → «Подтвердить бронь». Стоимость начисляется по снимку условий.
3. «Оплаты» → принять оплату и залог. Залог учитывается отдельно и не считается выручкой.
4. «Провести выдачу» → пробег, топливо, фото (с телефона откроется камера). Затем «Принять возврат» → предложенные доплаты, новые повреждения.
5. Удержание из залога: менеджер запрашивает, руководитель подтверждает.
6. Вернуть залог (руководитель или финансист) → «Закрыть заказ».
7. Попробуйте занять ту же машину на пересекающиеся даты — система откажет, учитывая 3 часа подготовки.

## Что сделано

- **Сайт проката:** выбор дат на первом экране, каталог с фильтрами и ценой за весь срок, карточка машины с калькулятором, цены в режимах «Рассчитать» и «Все тарифы», условия, контакты, заявка, перенаправления со старых адресов, `sitemap.xml`.
- **Один расчёт стоимости** (`lib/pricing.ts`) для сайта и CRM: сайт получает расчёт только с сервера.
- **Бронирование** (`lib/booking.ts`): временные резервы с истечением, брони, аренда, ТО и блокировки, буфер подготовки, просрочка возврата продолжает занимать машину. Проверка и запись выполняются атомарно.
- **CRM:**
  - «Сегодня»;
  - календарь (день, неделя, месяц);
  - заказы и карточка заказа с вкладками;
  - продление, замена машины, отмена и неявка;
  - осмотры с фото;
  - автопарк: тарифы с версиями, документы, ТО, повреждения;
  - клиенты с ограничением по направлениям;
  - заявки трёх направлений;
  - финансы: отчёты, журнал, сторно, экспорт CSV;
  - настройки правил и пользователей, журнал изменений.
- **Права** проверяются на сервере в каждом действии и при выдаче фото.
- **Журнал операций** только дополняется: изменить или удалить запись не даёт база. Исправления — сторно.

## Предположения и чего нет

- Правила округления суток, предоплаты, опоздания и буфера — **предположения** (помечены в расчётах). Их меняют в CRM → «Настройки».
- Тарифы перенесены с текущего сайта и ждут подтверждения владельцем (`docs/01-missing-data.md`).
- Нет: онлайн-оплаты, реальных уведомлений (SMS, Telegram), загрузки документов клиента, договоров, модулей продаж и сервиса (кроме заявок). Фото автомобилей — заглушки.
- SQLite подходит для теста и небольшой нагрузки. Для продакшена: `provider = "postgresql"` в `prisma/schema.prisma` и `DATABASE_URL` на сервер PostgreSQL, плюс ограничение `EXCLUDE` (см. `docs/02-architecture.md`).
